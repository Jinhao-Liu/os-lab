# Lab2 AI 提示词（Prompt）

本文件集中整理四个功能模块的 spec 与六份实现、测试提示词，便于独立查看和复用。
提示词为根据需求、最终实现及验证过程整理的版本；完整分析见[实验报告](实验报告.md)。
所有源码路径相对于本目录 labcodes/lab2。

按物理页初始化、Best-Fit、Buddy、SLUB 的顺序使用。完成 Best-Fit 时切换到
Best-Fit 管理器；完成 Buddy 时再切换到 Buddy；SLUB 在已有页分配器之上工作。
Buddy 和 SLUB 各有实现、测试两份提示词，需一起完成后再编译验证。

## 一、物理内存探测与页描述符初始化

### Spec

本练习的输入是设备树解析结果及框架中的地址布局；函数无参数、无返回值。成功后的状态是 va_pa_offset、npage 和 pages 正确，所有可管理页面都有描述符，且分配器只接收到排除 OpenSBI、内核镜像、描述符数组及对齐空隙后的完整空闲页。

我在 spec 中明确以下边界：内存基址或大小为零、基址加大小溢出、内存不能覆盖内核、描述符空间不足时终止初始化；可管理上界不能超过 PHYSICAL_MEMORY_END；内存末尾向下对齐，空闲区起点向上对齐；如果最后没有完整空闲页，就不调用 init_memmap()。

### 实现提示词

~~~text
请阅读 kern/mm/pmm.c、pmm.h、memlayout.h、mmu.h 和 kern/driver/dtb.c，
只实现 static void page_init(void)，保留现有框架与其他函数。
从 get_memory_base/get_memory_size 获取物理内存范围，无效信息必须 panic。
正确设置 va_pa_offset、npage、pages，并输出探测到的内存范围。
npage 是物理页号上界，描述符数量是 npage-nbase；Page 指针不是物理地址。
将可管理上界限制到 PHYSICAL_MEMORY_END 并向下按页对齐。
将描述符数组放到 end 之后的页边界，转换为物理地址检查其空间是否足够。
先初始化全部描述符为保留状态，再把描述符数组末尾之后的完整页注册到
init_memmap。排除 OpenSBI、内核及描述符本身；没有完整空闲页时不要注册。
处理范围加法溢出、内核不在内存范围和描述符放不下的情况。
使用框架提供的转换、对齐及状态宏，不修改 Page 布局，不硬编码空闲页数。
~~~

## 二、Best-Fit 连续物理内存分配

### Spec

Best-Fit 的接口和页状态约定沿用 First-Fit，但选择策略改为：遍历空闲链表，选择所有足够大块中最小的一块；存在恰好满足请求的块时即可停止。大小相同的候选保留先遇到的一个，不要求复杂的数据结构。

需要自行定义内部 free_area、各个管理函数及 best_fit_pmm_manager，并保持原有 basic_check() 和 best_fit_check() 不变。初始化、分割、回收、前后合并和空闲页计数都必须完整；分配失败不能修改状态。测试使用的 free_list、nr_free 约定需要保持一致。

### 实现提示词

~~~text
请参考 kern/mm/default_pmm.c，阅读 pmm.h 的 pmm_manager 接口，
在 kern/mm/best_fit_pmm.c 中实现完整 Best-Fit 连续物理页分配器。
自行定义 free_area、free_list、nr_free，各管理函数及 best_fit_pmm_manager，
保持文件已有 basic_check 和 best_fit_check 原样，不修改测试适配实现。
空闲链表按地址排序；分配时选择能容纳 n 页的最小块，恰好匹配可提前结束。
正确处理整个取走、分割余块、失败返回、页状态和空闲页数量。
释放时按地址插入，并依次合并物理相邻的前块、后块，覆盖空链表和尾插情况。
初始化登记应清除保留状态、设置引用计数，并允许与相邻空闲块合并。
在 pmm.c 引入 best_fit_pmm.h，并在 init_pmm_manager 中选择该管理器。
不要修改 page_init 和其他算法；通过原有测试并检查是否真正启用了 Best-Fit。
~~~

## 三、Buddy System 伙伴系统

### Spec

Buddy 复用 pmm_manager，保持 Page 布局不变，从零新增分配器和测试。每阶一条空闲链表，第 k 阶块含 2^k 页，按对应物理页数对齐。当前上界是 128 MiB，因此最大阶为 15。

初始空闲区域不一定按大块对齐、长度也不一定是 2 的幂，需要分解成多个合法块，不能丢掉剩余完整页，也不能跨过保留页。申请 n 页时向上取整到 2 的幂；例如 3 页实际占用 4 页，5 页实际占用 8 页，统计按实际占用量变化。

释放接口传入原申请页数 n，整个取整后的块一次归还，不支持部分释放。实现通过 n 对应的阶数与块首记录的大小进行核对，因此不会额外保存原始 n，也无法区分同属一阶的不同请求数。零页申请等非法调用用断言拒绝，合法但过大的申请返回 NULL。

### Prompt 1：生成实现并接入内核

~~~text
请阅读当前 ucore 的 kern/mm/pmm.h、memlayout.h、mmu.h、pmm.c、
default_pmm.c、best_fit_pmm.c 和 libs/list.h，在此框架上从零实现 Buddy
System 物理内存管理器，新增 kern/mm/buddy_pmm.c 和 buddy_pmm.h。

实现 init、init_memmap、alloc_pages、free_pages、nr_free_pages 回调，
定义 buddy_pmm_manager，并在 init_pmm_manager() 中切换到它。
保留已有 page_init()、First-Fit、Best-Fit 和原有测试，不改变 Page 布局，
不使用 malloc 或标准 C 库。Makefile 已自动收集 kern/mm/*.c，无需改造构建系统。

采用每阶一条循环双向链表，块大小为 2^k 页。依据框架内存上界确定最大阶，
本框架为 15。对非对齐、非 2 的幂大小的初始区间进行无损分解，保留所有完整页；
允许分批登记可用区间，但不能跨越保留页或未登记空洞。

请求 n 页时向上取整到最近的 2 的幂，从满足要求的最低可用阶逐级拆分。
记录分配块实际大小，空闲页计数减少实际占用页数。
释放时接受原请求 n，并释放对应完整块。使用物理页号异或块页数定位伙伴，
仅合并同阶且空闲的真正伙伴，递归合并并恢复统计。检查边界、页对齐、
保留状态、分配块首以及释放大小；不能因请求过大而发生移位溢出。

在头文件声明 void buddy_check(void)，由下一份提示词生成独立测试模块，
将管理器的 check 回调绑定到该函数，两部分一起编译。
说明状态约定、取整和整块释放语义，并给出验证结果。
为满足正常启动要求，可对已确认的启动过渡映射缺口作最小修复：
让开启分页后的物理启动 PC 在跳转到高位内核地址前仍可取指，保留原高位映射。
不要进行其他重构，算法复杂度不限。
~~~

### Prompt 2：生成正确性测试

~~~text
请阅读刚生成的 Buddy 实现与其接口契约，为它设计可复现的正确性测试。
新增 kern/mm/buddy_pmm_test.c，实现 buddy_check()，由内核初始化时的
pmm_manager->check 回调执行。测试结果用 assert 和 cprintf 表达。

通过 alloc_pages/free_pages/nr_free_pages 等公开接口验证：
1. 对 1、2、3、5、8、17 页请求，实际占用分别为 1、2、4、8、8、32 页；
   地址按实际块大小对齐，返回区域不重叠、不越界、不含保留页。
2. 使用原请求页数释放后统计完全恢复；超大请求失败且不改变状态。
3. 将全部可用页以单页请求耗尽，验证每个可用页恰好分配一次、无页丢失。
4. 在其余页面均被持有时，释放相邻但不是伙伴的两个单页块，请求两页必须失败。
5. 释放完整的对齐八页区域，验证逐级合并；再将其拆成两个三页请求，
   检查实际各占四页，释放后重新合并为八页。
6. 测试结束释放所有测试持有页面，恢复初始空闲页数量，避免耗尽内核栈。
不要假设接口未规定的任意块选择顺序。

测试必须区分请求页数和实际占用，不得把同一分配块的部分释放当作合法操作。
不得删除、放宽或修改先前 First-Fit/Best-Fit 的测试来迎合 Buddy。
执行真实 RISC-V 编译和 QEMU 启动，报告测试输出和任何限制。
~~~

## 四、简化 SLUB 内存对象分配

### Spec

第一层复用现有物理页分配接口，第二层提供 slub_init()、kmalloc(size)、kfree(ptr)。小对象按 16、32、64、128、256、512、1024、2048 字节分档，一个 slab 使用一页；大于 2048 字节的对象直接申请连续页。这里“任意大小”表示调用者可以传入不同的字节数，不表示底层恰好只消耗所申请的字节数。

返回地址保证 16 字节对齐。零字节、大小计算溢出或内存不足时返回 NULL，kfree(NULL) 无操作。其他释放参数必须是尚未释放的 kmalloc 原始返回指针。实现面向单 hart，不支持多核并发和任意非法指针检测。最后一个对象释放后，整页立即归还底层。

### Prompt 1：生成实现并接入内核

~~~text
请阅读当前 ucore 的 kern/mm/pmm.h、pmm.c、memlayout.h、buddy_pmm.c、
libs/list.h 以及 kern/init/init.c，在现有 Buddy 页分配器之上实现简化 SLUB，
新增 kern/mm/slub.c 和 slub.h。无需完整复现 Linux SLUB，主体思想清晰即可。

第一层复用 alloc_pages/free_pages/page2pa 和 va_pa_offset，不替换当前
pmm_manager，不改变 Page 布局和此前各分配器。第二层提供 slub_init()、
kmalloc(size_t size)、kfree(void *ptr)，在 kern_init 的 pmm_init 后初始化。
Makefile 已自动编译 kern/mm/*.c，不要引入新的构建系统。

按 16、32、64、128、256、512、1024、2048 字节建立固定大小对象 cache。
每个 slab 占一页，页首记录所属 cache、Page 描述符、空闲对象链表、在用数
等元数据，元数据和对象起始位置均按 16 字节对齐。将下一空闲对象指针存储
在空闲对象自身。每个 cache 维护 partial slab 链表，优先复用已有 slab；
页满时移出 partial，释放对象使满页变为 partial 时重新插入，整页空闲时
移出并归还 Buddy。不要为每次小对象申请单独分配一页。

大于 2048 字节的对象直接申请连续页，先把页首元数据计入总大小，再向上按页
取整。页首记录传给 Buddy 的原请求页数，释放时使用同一个请求页数，正确处理
Buddy 实际占用页数向上取整到 2 的幂的语义。保证用户可写区域不会覆盖元数据。

kmalloc(0)、大小加法溢出或内存不足时返回 NULL，kfree(NULL) 无操作；
其余释放参数必须是尚未释放的 kmalloc 原始返回指针。面向当前单 hart 环境，
slub_init() 只在 pmm_init() 后执行一次，不引入多核并发扩展。

声明 void slub_check(void)，由第二份提示词生成独立测试模块，并在初始化后
调用。保持旧分配器及其测试不变，说明接口与状态约定，执行真实 RISC-V 编译
和 QEMU 启动，报告实际结果。
~~~

### Prompt 2：生成正确性测试

~~~text
请阅读刚生成的 SLUB 模块及其 kmalloc/kfree ，新增
kern/mm/slub_test.c，实现 slub_check()，在 kern_init 的 slub_init() 后调用。
测试通过公开接口观察结果，使用 assert 和 cprintf，不得改动先前 Buddy、
Best-Fit、First-Fit 的测试，也不能放宽断言迁就实现。

覆盖以下情况：
1. 零字节、NULL 释放、极大或溢出请求，失败前后页计数不变。
2. 每个 cache 档位两侧边界，以及 2048、2049、4032、4033、4096、4097、
   8193 字节等大对象和跨页对象；地址按 16 字节对齐且有效区间不重叠。
3. 同时分配不同大小的多个对象，填入不同数据，逐字节检查数据隔离，
   按不同顺序释放，确认所有底层页最终归还。
4. 同一 cache 的对象共享 slab；在其他对象仍存活时释放、重新分配一个
   对象，验证空闲链表复用且不额外申请页，不破坏其他对象数据。
5. 分配足够多的小对象填满 slab 并扩展到第二页；释放满页中的对象，
   检查 full-to-partial 切换与复用，最终回收所有 slab。
6. 持有一个小对象后用 Buddy 耗尽其余页：原 slab 尚有空闲对象时，同档
   分配仍可成功；需要新 slab 的另一档位及大对象请求应失败。释放对象
   归还一页后应重新分配成功。测试结束归还所有测试占用的对象和页。

再新增 tools/slub_host_test.c 和 tools/check_slub_host.py，用按页对齐的
真实宿主机字节缓冲区模拟物理 RAM，并运行原 Buddy 和 SLUB 实现。保留
部分页为保留区，检查大对象实际页数、元数据边界及近整数上界请求；对
多个存活对象执行确定种子的随机分配释放，每次核对对齐、不重叠、地址
范围与全部存活对象的字节模式，最后确认无页泄漏。
只在测试夹具中用等价 builtin offsetof 替代框架旧宏以便运行检测器，
不得改动正式算法。用 ASan/UBSan 检查宿主机执行，并完成真实 RISC-V
编译和正常 QEMU 启动，报告实际验证结果。不要在内核自检中故意触发 panic。
~~~
